## 1. P3 做了什么

之前 `peer_relative` 排序的隐含假设是：**七个方面等权**——哪个方面亏得最多就先补哪个。这个假设从来没有被检验过。

P3 把它变成一个可估计的量。在酒店横截面上回归

```
y_i = c + Σ_a v_a · x_{i,a} + ε
```

- `x_{i,a}` = 酒店 i 在**检测折 A** 上方面 a 的平均情感（fold-pure，状态只来自一个折）
- `y_i` = 酒店 i 在**结果折 B** 上的加权平均评分（与 A 互斥）
- 反过来 B→A 再估一次，两个方向互为复现

得到的 `v` 就是"**1 个标准差的方面情感，对应多少评分点**"。

## 2. Q1：v 是真的，不是过拟合

| 方向 | n | 折外 CV R² | placebo R² | 比值 | 目标 sd |
|---|---|---|---|---|---|
| A→B | 1300 | **+0.4413** | −0.0015 | **304.2** | 0.617 |
| B→A | 1292 | **+0.4601** | −0.0048 | 96.7 | 0.606 |

对照 P4b 的探测结果：折分离的**季度变化** R² 只有 0.0010，而**酒店横截面水平** R² 是 0.4490。P3 就是冲着那 0.449 去的，拿到了 0.441——说明这个截面信号是真实的、可被标准方法拿到的，不是什么巧妙特征工程的产物。

### 系数（评分点 / 1 SD，A→B，bootstrap 300 次）

| 方面 | 系数 | se | t | 95% CI |
|---|---|---|---|---|
| room | **+0.2786** | 0.0182 | +15.27 | [+0.2423, +0.3126] |
| service | **+0.2599** | 0.0193 | +13.56 | [+0.2208, +0.2961] |
| noise | +0.0814 | 0.0140 | +5.89 | [+0.0559, +0.1092] |
| value | +0.0004 | 0.0138 | −0.02 | [−0.0260, +0.0287] |
| breakfast | −0.0102 | 0.0111 | −0.89 | [−0.0324, +0.0111] |
| cleanliness | −0.0814 | 0.0153 | **−5.34** | [−0.1116, −0.0515] |
| location（不可行动） | −0.0564 | 0.0216 | −2.67 | [−0.0987, −0.0156] |

> 说明：上表是 A→B 单方向。实际落盘的 `value_vector.json` 取 **A→B 与 B→A 两个方向的平均**（room +0.2843 / service +0.2659 / noise +0.0826 / value −0.0091 / breakfast −0.0129 / cleanliness −0.0988 / location −0.0576），两个方向本身高度一致。

归一化后（在 6 个可行动方面上均值=1，负值截断），条件规格的 v 实际是：

> **room 2.70 / service 2.51 / noise 0.79 / value 0 / breakfast 0 / cleanliness 0**

也就是说， shipped 的"补最亏的方面"被改成了"**优先补 room 和 service，cleanliness 和 breakfast 基本不推荐**"。

## 3. Q2：能迁移

两个**不相交**酒店半区各自估一个 v，在 6 个可行动方面上算相关系数：**0.982**（sd 0.010，40 次重复 100% 为正，全 7 方面 0.979）。策略实验里交叉核对也是 0.985。

这不是"同一批数据拟合两次"——是两批完全不同的酒店给出了同一个向量。

## 4. Q3：⚠️ 这一节基本是同义反复，请谨慎读

`transfer_experiment` 的奖励定义是"**被选中方面的 v 值**"——也就是用 v 本身给策略打分。所以 `value_aware` 赢 `peer_relative` 和 `random_uniform` 是**定义上必然**的，不构成任何证据。

表里唯一不循环的一行是 `placebo_permuted_v`：**同一组权重，随机打乱到不同方面上**。它保留了"集中权重有帮助"的部分，只摧毁了"权重与方面的对应关系"。这才是策略真正的贡献。

| 策略 | 价值 | 说明 |
|---|---|---|
| random_uniform | 1.0000 | 基准 |
| peer_relative（现役） | 1.6066 | shipped 行为 |
| placebo_permuted_v | 1.6844 | 权重对，方面错 |
| **value_aware** | **2.5794** | 权重和方面都对 |
| oracle_best_v_eval | 2.7019 | 上界 |

- `value_aware − placebo_permuted_v` = **+0.89496**（se 0.085，t=+10.50，**98%** 重复为正）
- placebo 比值 **2.31**（≥1.5 才算过线）
- 与 `peer_relative` 的一致率 **59.2%** ⇒ **40.8% 的推荐会改变**

**能说明的**：权重的"对齐"确实额外贡献了价值，不是随便一组非均匀权重都能拿到。

**不能说明的**：这个价值对用户/酒店有任何实际意义——因为奖励本身就是 v。

## 5. Q3b：唯一碰真实评分的测试

做法：只用策略选中的那一个方面，`y = a + b·level(选中方面)` 在训练酒店上拟合斜率，在**未见过的酒店**上算 R²。

### 一个必须说清的修正

第一版 Q3b 只对比了 `random_uniform`，结果出现"随机选方面（0.0441）比现役的最大缺口策略（0.0149）还好"的反直觉现象。原因不是随机器更好，而是：

- `random_uniform` 的预测变量是**六个方面的混合**，拟合出的斜率是各方面斜率的**平均**，天然继承了 room/service 的强信号；
- `largest_deficit` 永远挑最极端低的那个方面，被测量噪声主导。

所以 `random_uniform` 是**参照物，不是地板**。我给 Q3b 加了 `placebo_permuted_v`（同样权重、打乱方面）作为公平地板，并补了 3 个测试锁住这个设计（`tests/test_effect_p3.py::SingleAspectProbeTests`）。

### 结果（40 次重复）

| 策略 | 条件规格 R² | 边缘规格 R² |
|---|---|---|
| oracle_marginal（上界） | 0.3341 | 0.3341 |
| **value_aware** | **0.0762** | 0.0345 |
| placebo_permuted_v | 0.0580 | 0.0314 |
| random_uniform（参照） | 0.0441 | 0.0441 |
| largest_deficit（现役） | 0.0149 | 0.0149 |

| 对比（条件规格） | 差 | se | t | 正比例 |
|---|---|---|---|---|
| value_aware − placebo_permuted_v | +0.01818 | 0.00939 | **+1.94** | 60% |
| value_aware − largest_deficit | +0.06129 | 0.00658 | +9.32 | 98% |
| value_aware − random_uniform | +0.03212 | 0.00732 | +4.39 | 62% |

**诚实解读**：对齐带来的增益是 **+0.018 R²**，t=1.94，只在 60% 的重复里为正——**方向对，但弱**。相对上界 0.334，我们只拿到 23%。而且：

- 边缘规格在这个测试上是**失败的**：0.0345 vs 随机 0.0441（差 −0.0095，t=−3.85，只有 20% 重复为正）。原因是边缘向量归一化后太平（room 1.97 / service 1.48 / noise 1.22 / cleanliness 1.00），几乎不改变选哪个方面，于是继承了 `largest_deficit` 的弱行为。

## 6. Q4（决定性）：P4 复核——换策略，收益没动

把 `value_aware` 加进 P4 的直接法（Direct Method）框架重跑，四种配置（A→B / B→A × forward / contemp），价值向量做**交叉拟合**（每家酒店的 v 都是不用它自己估出来的）。

| 配置 | value_aware − peer_relative | se | t | value_aware − random | t |
|---|---|---|---|---|---|
| A→B forward | −0.00021 | 0.00490 | −0.04 | −0.00085 | −0.12 |
| B→A forward | −0.00483 | 0.00543 | −0.89 | −0.00484 | −0.64 |
| A→B contemp | +0.00434 | 0.00459 | +0.95 | +0.00518 | +0.81 |
| B→A contemp | +0.00257 | 0.00517 | +0.50 | +0.00244 | +0.33 |

- 与 `peer_relative` 一致率 **0.482–0.490** ⇒ 超过一半的推荐变了，但估计收益差**连符号都不确定**
- `location` 被当作行动推荐的违规率：**0.000**（所有策略）
- 检测阈值：效应要超过约 **0.013 评分点**才看得见，**没有任何东西接近**

这完全复现了 P4 的 `AMBER_NO_DISCRIMINATION`：不是 P3 的向量不好，是**这个数据集的决策回报太弱，区分不了任何策略**。

## 7. 条件 vs 边缘规格：一个必须写进论文的分歧

| 方面 | 条件（多变量） | 边缘（单变量） | 符号一致 |
|---|---|---|---|
| location | −0.0564 | +0.0196 | **否** |
| cleanliness | −0.0814 | +0.1801 | **否** |
| breakfast | −0.0102 | +0.0470 | **否** |
| room | +0.2786 | +0.3551 | 是 |
| service | +0.2599 | +0.2662 | 是 |
| noise | +0.0814 | +0.2199 | 是 |

设计矩阵条件数 **3.1**，最大非对角相关 **0.589** —— 共线性很轻，**这不是数值假象**。

真实含义：cleanliness 和 location 的"正向总关联"里，绝大部分是被 room/service 解释掉的溢出。一旦控制住 room 和 service，它们反而略负。

**选哪个？没有干预数据就无法判定。** 我选了条件规格，理由是可证伪的：只有它在 Q3b 上同时赢过打乱向量和随机参照。这个选择已写进 `value_vector.json` 的 `recommended_spec` 字段和理由里，没有藏起来。

## 8. 这意味着什么，下一步怎么走

### 已经拿到的（可以写进论文 / 演示）

1. **一个真实的、可迁移的、带不确定性的方面价值向量**——R² 0.44、placebo 比值 304、半半相关 0.98。这是这个项目里第一个在横截面上站得住的量化结果。
2. **排序从"等权启发式"升级为"数据驱动 + 可解释"**，且严格保持现役策略的全部门控（资格、可靠性、行动性），只是在门控内改排序。
3. **41–51% 的推荐会改变**，从不推荐不可行动的 location。这本身是一个可写的产品性发现：现役策略推荐的东西，有近一半在"哪个方面更值钱"这个维度上是错的。

### 没拿到的（必须诚实说）

**"增加酒店收益"没有证据，而且按当前路线拿不到。**

原因不在算法：P4 已经证明，在这个数据集上，任何两个策略之间的决策回报差异都小于 0.013 评分点的检测阈值。换了排序、换了对齐、换了向量，回报都是 0。

### 三条出路（按我的推荐排序）

| 路线 | 做什么 | 可行性 | 代价 |
|---|---|---|---|
| **A. 换 estimand（推荐）** | 不再追求"让评分涨"，改成证明"在相同评分分布下，系统推荐的是经理真正会采纳、且采纳后收益最高的动作"。需要一批真实的干预记录（哪怕几十条），或者与酒店合作的 A/B | 中 | 需要外部数据/合作 |
| **B. 改奖励模型** | 承认"评分点变化"不是决策相关量，改用评论量与情感对未来**预订/价格**的预测力做奖励。需要 ADR / 入住率 / 价格弹性 | 中 | 需要外部数据；你说的"收益=推算"正是这里的上限 |
| **C. 定位为可解释性贡献** | 论文里明确声明：本系统优化的是"决策一致性与可解释性"，不是"经证明的收益提升"。把 P1–P4 的零结果本身作为贡献 | 高 | 放弃了原始目标 |

**我的判断**：C 是保底，A 是唯一能真正兑现原始目标的路径，但它**不是纯算法问题**——需要数据。这一点必须在下一次汇报时明确讲出来，否则会一直在这个数据集上空转。
