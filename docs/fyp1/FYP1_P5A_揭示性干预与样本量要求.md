## 1. A 路线的可识别性审计：缺什么

原始目标要求打通这条链：

```
排序策略 → 推荐动作 → 经理是否采纳？ → 酒店整改 → 评分回升 → 需求上升 → 收益上升
                      ↑ 观测不到                ↑ 观测不到        ↑ 观测不到
```

对现有数据逐项核对：

| 环节 | 需要的数据 | 数据集里有吗 | 证据 |
|---|---|---|---|
| 经理是否采纳 | 采纳/驳回日志、整改工单 | **无** | 原始 Booking 评论字段仅 17 列（地址、评分、日期、正负面文本、标签、经纬度等），无任何管理侧字段 |
| 收益 | ADR、入住率、RevPAR | **无** | 同上 |
| 需求 | 预订量 | **无** | 只有评论量，不是预订量 |
| 价格（外部尝试） | 可与面板酒店连接的价格 | **有但连不上** | `data/processed/hotels_all.csv` 821 行、321 行有价（EUR，中位数 129），**全部为比利时城市**（Brussels/Bruges/Antwerp/Ghent/Liège）；面板城市为 Paris 458 / London 399 / Barcelona 211 / Milan 162 / Vienna 158 / Amsterdam 105 → **交集为空集** |

ID 映射本身是通的（已验证）：`hotel_id = 'd1_europe:' + legacy_hotel_id[:12]`，1493/1493 匹配。所以问题不是键，是**没有那张表**。

**ADR 129 只能用做量级锚点，不能连接、不能参与任何估计。** 报告中已显式标注来源与「scale anchor only, not joined」。

## 2. 能估计的最近替代：揭示性干预事件研究

既然没有干预日志，就用**评论里持续性的方面情感跃迁**作为干预的揭示性代理：

```
event(a) at (i,t)  ⟺  net_a^D[t] − net_a^D[t−1] ≥ τ
                   且  net_a^D[t+1] − net_a^D[t−1] ≥ τ · persist_frac
```

- **折纯度**：在检测折 A 上识别事件，在互斥折 B 上测结果（`Y^O`），镜像方向 B→A 同样跑。切断「同一条评论同时贡献提及与评分」的机械耦合。
- **结果**：`dY = Y^O[t+1] − Y^O[t−1]`，跨事件跨度。
- **对照组**：同一酒店-季度内**任何方面都没有事件**的单元。
- **可靠性下限**：t−1、t、t+1 三期的方面测量可靠性均需 ≥ 0.30。
- **无 IPS/SNIPS**：`wave6/policy.json` 的 `no_ips_snips: true` 与评审规则 R1 P2 明令禁止把离线评估包装成 IPS/SNIPS；且无记录策略 → 无倾向性得分。本设计是**直接法（结果回归 + DID）**，全程未估计任何策略比值。

## 4. Q2 评分回报是方面特异的吗

**这是本次最关键的设计决定：拆成两条独立主张，各自要求跨折复现。** 因为 A→B 与 B→A 在特异性上真实地给出了不同答案——只跑一个方向就会得出错误结论，而且无论跑哪个方向都像是「有发现」。

### 主张一：改进是否有回报 → **复现（REPLICATED_ACROSS_FOLDS）**

| 方向 | 合并 ATT（评分点） | t | 前趋势 t−2→t−1 | 判定 |
|---|---|---|---|---|
| A→B | **+0.0656** | 3.46 | −0.021 (t=−0.94) | ✅ |
| B→A | **+0.0652** | 3.43 | −0.0425 (t=−2.11) | ✅ |

两个方向几乎给出同一个数字，这在自指设计里不是理所当然的（P3 的向量就做不到）。A→B 前趋势干净。

### 主张二：哪个方面回报最高 → **方向依赖（DIRECTION_DEPENDENT）**

| 方向 | best−worst 差距 | placebo 差距 | 比值 | p | 被点名的方面 |
|---|---|---|---|---|---|
| A→B | 0.1152 | 0.1119 | **1.029** | 0.402 | cleanliness |
| B→A | 0.2035 | 0.1092 | **1.863** | 0.008 | value |

- A→B：差距和随机置换 placebo 一样大 → **不是特异性，是次序统计量的膨胀**。
- B→A：比值 1.86、p=0.008，看起来成立——**但这个方向的前趋势 t=−2.11 未通过**，事件前这些酒店已经在动了，那部分差距是均值回归，不是回报。
- 两个方向点名的方面也不同（cleanliness vs value）。

**所以：不采纳任何「X 方面最值钱」的表述。**

### 支撑性证据（两个方向一致）

- **特异性检验**（事件方面是否比同酒店-季度的其他方面动得更多）：A→B +0.0386 (t=8.23)、B→A +0.0407 (t=8.44) → **事件本身确实是方面特异的**。特异的是「发生了什么」，不是「哪个更值钱」。
- **恶化臂**（持续性下跌）：A→B 合并 −0.0118 (t=−0.64)、B→A −0.0461 (t=−2.44)。方向与改进臂相反，符号正确，但幅度不对称（不对称本身是合理的：损失厌恶/下界效应，不能反过来当作改进臂的证据）。
- **阈值敏感性 τ ∈ {0.20, 0.25, 0.30, 0.40}**：合并效应稳定（t=2.57–4.45，τ=0.20 时 4.45），但**最佳方面的比值在 1.34 / 1.04 / 1.18 / 0.66 之间跳，被点名的方面 service→cleanliness→service→value 来回翻转**。效应稳健、排序不稳健——这不是噪声大小的问题，是**根本没识别出排序**。

## 5. Q3 P3 的价值向量能迁移到这个靶标吗 → 不能

交叉拟合：γ 在一个酒店半区上由揭示性事件估计，应用到另一半区的策略选择上。

- `V(value_aware) − V(peer_relative)` = **+0.0209**（se 0.0032，92% 重复为正）
- 打乱 γ 的零分布：均值 +0.00045，sd 0.0271
- **z = 0.753，p = 0.227 → NO_TRANSFER**

这个结果不意外，也不构成对 P3 的否定：P3 的 v 是在**水平**上估的（横截面：方面画像 → 评分水平），这里的 γ 是**变化**上的（事件 → 评分变化）。两者是不同的估计目标。**不要把它们混用。**

## 6. Q4 还差多少数据（功效 / MDE）

- 每个酒店-季度的结果噪声：σ = **0.909 评分点**
- 当前每个方面的中位数事件数：**227**
- **当前样本能检出的最小方面间差异：0.171 评分点**（且还需先过 placebo）

要达到更小的效应，需要的**已记录干预数**：

| 目标效应（评分点） | 每个方面需要的 n | 6 个可行动方面合计 | 现在能检出吗 |
|---|---|---|---|
| 0.02 | 32,437 | 194,622 | 否 |
| 0.05 | 5,190 | 31,140 | 否 |
| 0.10 | 1,298 | 7,788 | 否 |
| 0.20 | 325 | 1,950 | **是** |
| 0.50 | 52 | 312 | **是** |

收益折算（ADR 锚点 129.0，来自爬取的 Booking 价格，**比利时样本，非面板城市，仅作量级锚点、未连接**；弹性是**外部假设，非本数据估计**）：

| 假设「每评分点 = x% 收益」 | 对应 MDE（% 收益） |
|---|---|
| 1% | 0.171 |
| 2% | 0.343 |
| 5% | 0.857 |

**这张表把「我们需要干预记录」变成了「我们需要 N 条干预记录」**——这是可以拿去谈合作、谈数据、或者写进论文 limitation 的具体数字。

## 7. 能说什么 / 不能说什么

✅ **可以说**（有跨折复现 + 前趋势 + placebo 支撑）：

1. 「持续性的方面改进之后，评分会回升约 +0.065 点（t≈3.4），这在两个互斥折方向上都成立。」
2. 「评论中检测到的事件是方面特异的：发生事件的方面确实比其他方面动得更多（t≈8.2–8.4）。」
3. 「因此可辩护的推荐逻辑是：对最薄弱、且测量可靠的方面采取行动。」
4. 「要判定方面间的回报差异，需要约 N 条已记录干预（见表），不是更好的估计量。」

❌ **不能说**：

1. 「针对 value / cleanliness 投入，因为它回报最高。」——方向依赖，且唯一显著的方向前趋势未通过。
2. 「本系统能提升酒店收益。」——采纳与收益两个环节均无观测。
3. 任何把 ADR 129 参与计算后得到的收益数字——样本国家不同、未连接、弹性是假设。
4. 任何形式的 IPS / SNIPS 包装——规则禁止，且本设计不需要。

**注意：现役的 peer-relative 排序实现的正是第 3 条。** 所以本轮的实际产物不是「新算法」，而是「给现役算法一个此前没有的正当性证明，并划清它不能主张的边界」。

## 8. 要真正兑现原始目标，需要什么

按优先级：

1. **干预/采纳日志**（决定性）。字段最小集：`hotel_id, action_aspect, action_date, adopted(0/1)`。有了它，主张二可以直接估，且样本量要求见 §6。
2. **收益序列**：`hotel_id, period, ADR, occupancy`（或 RevPAR）。有了它才能把评分点换成钱，而不靠外部弹性假设。
3. **价格/需求**：若拿不到收益，至少要有面板城市（Paris / London / Barcelona / Milan / Vienna / Amsterdam）的价格，当前爬取的比利时样本用不上。

三者都有 → 原始目标可证。只有 1 → 可证「采纳后评分回升」，收益仍需折算。都没有 → 只能停在 §7 的第 1–4 条，即路线 C 的定位。
