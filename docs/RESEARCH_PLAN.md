# 科研方案：让酒店建议有依据、能执行、懂得保留意见

一句话：从住客评论中找出酒店的具体问题，再判断“经理现在最值得处理什么”，并检验这套建议规则是否比简单做法可靠。当前主线是酒店经理端；游客选酒店与实际增收另列扩展，避免把多个尚未验证的目标混在一起。

## 研究问题

- RQ1：机器能否分清客人在夸/批评哪个方面？用自动独立标注诊断错分、漏检和模糊项，不以模型共识代替真实准确率。
- RQ2：加入“能不能改”和“证据够不够”，是否能减少不合理建议，同时保持有用的建议覆盖？这是当前主贡献。
- RQ3：附近酒店的信息是否带来稳定的额外预测信息？这是可以得到负结果的辅助问题，不把相关性说成竞争或干预效果。

阶段 2 与阶段 3 的纯代码工作可分别推进。先冻结阶段 4/5 的比较方案和指标，再跑实验；不能为了结论好看反复调整门槛。本轮 210 项是诊断/开发集，任何看过它的模型或规则不能拿它做最终独立测试。若后续训练模型，同一评论、近重复文本和酒店应避免跨开发/测试泄漏；模型可能见过公开源数据的预训练污染无法由本流程排除。

模型评价建议时也应隐藏方法名称、随机呈现顺序、按预先写好的证据支持/清晰度量表独立打分，并报告分歧。这只能支持“模型评价下的建议质量”；没有真实行动、成本和结果数据，就不做“经理采纳率/预订增长/利润提升”的结论。这些业务数据不是通过多找一个模型就能产生的。

## 预先固定的实验口径

主要结果优先报告规则有效性和取舍：不可行动建议比例、证据缺失时强推比例、可给建议酒店比例、重抽样后首选方面一致性，以及建议相对共同参考评分的分布。拒绝越多不一定越好，须画覆盖率与错误风险的关系；不存在独立真值时称“模型参考分歧风险”。评价抽样按城市、酒店和证据量报告，采用酒店层级重抽样区间，不能把同一家酒店多个方面当完全独立样本。若做模型参考 Macro-F1，必须同时给出参考标签保留率及 unresolved 分布，避免只报告容易的一致样本。

辅助预测继续沿用现有完整季度、交叉拟合与预先指定参照。当前误差 0.370384→0.369371、差值区间跨零，尚不能证明附近信息稳定提升预测。456 个严格事件是评论感知变化，不是已知管理干预；这批旧结果原样保留，不因标注完成自动升级。

## 创新怎样讲才准确

待验证的贡献是把“附近参照、可执行性、证据可靠性、必要时不建议”整合到酒店经理决策，并用统一策略、消融和可追溯证据检验价值。大模型标注是质量控制手段，本身不自动构成创新；中文界面是交付价值。方面情感分析已有 [SemEval-2014 原始任务](https://aclanthology.org/S14-2004/)，拒绝不可靠预测已有 [Selective Classification 研究](https://proceedings.neurips.cc/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html)，因此不能把这些组件称为首创。

当前仅核对这些基础方法出处，尚未完成酒店决策领域的系统文献查重；“组合在本场景有价值”仍是要通过实验验证的假设。模型或人工参考标签都可能有误，一致性不能独自解决有效性问题，相关讨论见 [All that Glitters](https://aclanthology.org/2025.findings-naacl.120/)。
